# M2 — Persistence (Drift/SQLite) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give MiCasa a local SQLite schema (via Drift) and typed DAOs for
rooms, chores, chore completions, entropy state, and runs — the durable
store that later milestones (M3 onward) will read and write through.

**Architecture:** One `AppDatabase` (`lib/data/database.dart`) declares five
tables and five matching DAOs, each pair added in its own task. Tables live
in `lib/data/tables/`, DAOs in `lib/data/daos/`, one file per table/DAO.
Tests open a fresh `NativeDatabase.memory()` per test — no file I/O, no
shared state between tests. This milestone does **not** call into
`lib/simulation/`; DAOs only shape and persist data. Wiring M1's
`EntropyEngine`/`DurationLearner`/`ComboEngine` to these DAOs is M6's job
(combo & momentum integration), once a real run UI exists to drive it.

**Tech Stack:** Drift 2.34 (already in `pubspec.yaml` from M0: `drift`,
`drift_dev`, `build_runner`, `path_provider`, `path`), `NativeDatabase`
(`package:drift/native.dart`) — not `sqlite3_flutter_libs` or the
deprecated `FlutterQueryExecutor` (CLAUDE.md is explicit about this).

**Spec:** `docs/micasa_spec.md` §5.3 (SQLite is the source of truth,
local-first, no backend); `docs/superpowers/specs/2026-08-24-phase-0-roadmap-design.md`
M2 definition ("Schema + DAOs for rooms, tasks, chores, entropy state, run
history, momentum").

## Global Constraints

- Local-first, no backend, no login, no sync in Phase 0 (CLAUDE.md).
- Use `NativeDatabase` (`package:drift/native.dart`), never
  `sqlite3_flutter_libs` or `FlutterQueryExecutor` (CLAUDE.md).
- `lib/data/` must never import from `lib/simulation/` or
  `lib/presentation/` in this milestone — it is a pure persistence layer.
  Orchestration that combines DAOs with `lib/simulation/` engines is
  explicitly out of scope for M2 (roadmap doc, M6 owns that wiring).
- Content (room types, tasks, adjacency edges) stays in `content/` JSON,
  never duplicated into the database — tables here store only per-home
  *instances* (a room the user actually added, a chore the user actually
  has) and *history* (completions, runs), referencing content by string
  ID (`roomTypeId`, `taskDefinitionId`).
- Every table gets a matching DAO in the same task; no orphaned schema.
- Drift's generated `*.g.dart` files are committed alongside their
  source, same as any other generated-and-checked-in code in this repo.
- Run `flutter test` and `flutter analyze` from the worktree root with
  `$env:PATH = "C:\flutter\bin;$env:PATH"` prefixed in PowerShell (Flutter
  isn't on PATH by default in this environment).

```dart
// lib/data/database.dart
import 'dart:io';

import 'package:drift/drift.dart';
import 'package:drift/native.dart';
import 'package:path/path.dart' as p;
import 'package:path_provider/path_provider.dart';

import 'daos/rooms_dao.dart';
import 'tables/rooms_table.dart';

part 'database.g.dart';

@DriftDatabase(
  tables: [Rooms],
  daos: [RoomsDao],
)
class AppDatabase extends _$AppDatabase {
  AppDatabase(super.executor);

  AppDatabase.open() : this(_openConnection());

  @override
  int get schemaVersion => 1;

  @override
  MigrationStrategy get migration => MigrationStrategy(
        beforeOpen: (details) async {
          await customStatement('PRAGMA foreign_keys = ON');
        },
      );

  static LazyDatabase _openConnection() {
    return LazyDatabase(() async {
      final dbFolder = await getApplicationDocumentsDirectory();
      final file = File(p.join(dbFolder.path, 'micasa.sqlite'));
      return NativeDatabase.createInBackground(file);
    });
  }
}
```

The `PRAGMA foreign_keys = ON` line makes SQLite enforce the
`.references(...)` foreign keys that later tasks add — SQLite ignores them
by default unless this pragma is set on every connection.

```dart
part 'chores_dao.g.dart';

@DriftAccessor(tables: [Chores])
class ChoresDao extends DatabaseAccessor<AppDatabase> with _$ChoresDaoMixin {

  Future<List<Chore>> getActiveChores() =>
      (select(chores)..where((c) => c.isRemoved.equals(false))).get();
}
```

```dart
// lib/data/daos/chore_completions_dao.dart
import 'package:drift/drift.dart';

import '../database.dart';
import '../tables/chore_completions_table.dart';

part 'chore_completions_dao.g.dart';

@DriftAccessor(tables: [ChoreCompletions])
class ChoreCompletionsDao extends DatabaseAccessor<AppDatabase>
    with _$ChoreCompletionsDaoMixin {
  ChoreCompletionsDao(super.db);

  Future<void> recordCompletion(ChoreCompletionsCompanion completion) =>
      into(choreCompletions).insert(completion);

  Future<List<DateTime>> getCompletionHistory(String choreId) async {
    final rows = await (select(choreCompletions)
          ..where((c) => c.choreId.equals(choreId))
          ..orderBy([(c) => OrderingTerm(expression: c.completedAt)]))
        .get();
    return rows.map((r) => r.completedAt).toList();
  }

  Future<List<ChoreCompletion>> getRecentCompletions(int limit) =>
      (select(choreCompletions)
            ..orderBy([
              (c) => OrderingTerm(
                    expression: c.completedAt,
                    mode: OrderingMode.desc,
                  )
            ])
            ..limit(limit))
          .get();
}
```

- [ ] **Step 4: Write the DAO**

```dart
// lib/data/daos/runs_dao.dart
import 'package:drift/drift.dart';

import '../database.dart';
import '../tables/runs_table.dart';

part 'runs_dao.g.dart';

@DriftAccessor(tables: [Runs])
class RunsDao extends DatabaseAccessor<AppDatabase> with _$RunsDaoMixin {
  RunsDao(super.db);

  Future<void> startRun(RunsCompanion run) => into(runs).insert(run);

  Future<void> endRun({
    required String runId,
    required DateTime endedAt,
    required int momentumChainLength,
  }) =>
      (update(runs)..where((r) => r.id.equals(runId))).write(
        RunsCompanion(
          endedAt: Value(endedAt),
          momentumChainLength: Value(momentumChainLength),
        ),
      );

  Future<List<Run>> getRunHistory() => (select(runs)
        ..orderBy([
          (r) => OrderingTerm(
                expression: r.startedAt,
                mode: OrderingMode.desc,
              )
        ]))
      .get();
}
```
